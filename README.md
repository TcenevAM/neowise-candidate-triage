# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Выполненное решение

Нужен Node.js **20+**. Установка пакетов, API-ключи и внешние сервисы не нужны.

```sh
# Запуск; затем открыть http://127.0.0.1:3000
node server.mjs

# В другом терминале, из корня репозитория
node --test
```

Другой порт: `PORT=3100 node server.mjs` (bash) или
`$env:PORT=3100; node server.mjs` (PowerShell).

### Контракт API

`POST /api/triage`, `Content-Type: application/json`:

```json
{"text":"Когда будет доставка?"}
```

| Ситуация | HTTP | Тело ответа |
| --- | --- | --- |
| Битый JSON, отсутствующий `text`, неверный тип или только пробелы | 400 | `{"status":"invalid_input"}` |
| Известная тема и непустой черновик | 200 | `{"status":"ready","topic":"delivery","draft":"…"}` |
| Ошибка, таймаут или некорректный результат модели | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

В `handleTriage` (`server.mjs`) результат модели проверяется **после** JSON-разбора:
допускаются только темы `delivery`, `pricing`, `other` и строка `draft`, непустая
после `trim()`. В ответ попадают только проверенные поля, без распространения
произвольных полей модели. `Promise.race` ограничивает ожидание 300 мс;
`AbortController` также отменяет работу имитатора. Таймер очищается после результата.
Поведение `mock-ai.mjs` сохранено дословно.

### Что видит менеджер

- При успехе — понятное название темы и редактируемый черновик. Решение об отправке
  остаётся за менеджером; страница ничего не отправляет клиенту автоматически.
- При сбое — сообщение «Нужен ручной разбор», без старой темы и старого черновика.
  Исходный текст заявки остаётся на странице.
- Новый запрос и изменение текста очищают предыдущий результат. Поздний ответ,
  ошибка или завершение старого запроса не меняют состояние нового запроса:
  перед обновлением проверяется его порядковый номер. Отмена предыдущего `fetch`
  — дополнительная мера. В браузере есть отдельный сетевой таймаут 2 секунды.

### Проверки

`node --test` запускает 20 тестов без сторонних зависимостей:

- `test/server.test.mjs` поднимает настоящий HTTP-сервер на свободном порту:
  неверные тела запросов, все три темы, все пять маркеров сбоя, срок ожидания
  и успешная обработка после таймаута.
- `test/page.test.mjs` исполняет настоящий скрипт страницы в Node VM с управляемыми
  ответами сети и минимальным DOM. Проверяет очистку черновика, сетевые ошибки,
  некорректные ответы, обратный порядок ответов, ошибки старого запроса,
  изменение ввода и отмену по таймауту. Имитатор сети намеренно игнорирует отмену,
  чтобы проверить защиту номером запроса независимо от `AbortController`.

Для ручной проверки в браузере: сначала ввести «Когда доставка?», затем по очереди
`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`.
После каждого сбоя должен отображаться ручной разбор без предыдущего черновика.

### AI и польза для менеджера

Для разработки решения использован **OpenAI Codex**. В самом приложении работает
только выданный имитатор, платных вызовов моделей нет. Проверка результата —
исполнение автотестов на реальном HTTP-сервере и проверка страницы в headless Chromium.

Польза: менеджер быстрее получает тему и заготовку ответа, а сбой AI явно передаёт
заявку на ручной разбор. Улучшение можно измерить временем обработки заявки с учётом
исправлений и долей черновиков, принятых без правок.
